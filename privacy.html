Privacy Policy

Last updated: September 9, 2026

Tyrone Command Center is a local desktop application. There is no company server that receives, stores, or sells your data. This policy describes exactly what the App itself processes on your own device and what it sends directly to the platforms you connect.

1. Summary

  • The App does not have its own backend server. It runs entirely on your computer.
  • The App does not include any analytics, tracking, or advertising SDK of any kind.
  • Data the App reads from a connected platform is requested directly from that platform's own official API, using credentials you explicitly authorize, and is stored only on your own device.
  • The App never sells, rents, or shares your data with anyone, because it does not transmit your data to any party other than the platform you explicitly connected.

2. Information processed when you connect an account

When you connect an account, the App opens that platform's own official sign-in page in your browser. You authorize a specific, limited set of permissions ("scopes") on that page — the App never sees or asks for your password.

TikTok (Login Kit)

Current authorized scope: user.info.basic. This returns only: your TikTok open ID, display name, and avatar URL. The App does not currently request your TikTok username, follower/following/like/video counts, or your video list — those require additional scopes the App does not request today.

YouTube (Google OAuth)

Scopes: youtube.readonly and yt-analytics.readonly. This returns your channel's basic profile info, video list, and read-only analytics/statistics for the channel you authorize. The App never requests upload, comment, or account-modification permissions.

Instagram (Meta Graph API)

Scopes: instagram_business_basic and instagram_business_manage_insights. This returns basic business-account profile info and insights for the account you authorize.

3. Local application data

The App stores the following only in a local application-support folder on your own computer (never transmitted anywhere):

  • Account list — display name, username, avatar URL, platform, and connection status for each account you've added. This file never contains an access token or refresh token.
  • OAuth tokens — access and refresh tokens are stored in a separate location, encrypted at rest with AES-256-GCM, in files only your own macOS user account can read (owner-only file permissions). Tokens are never written into the account list file, never sent to the App's UI/frontend code as plain values, and never written to any log file.
  • Optional personal notes ("Second Brain") — if you choose to connect a folder of your own Markdown notes, the App indexes titles, tags, and links from those files locally so its assistant feature can reference them. This never leaves your device and is never sent to any third party.
  • Diagnostic log — a local log of connection attempts (e.g. "TikTok: opening browser," "token exchange failed") used for troubleshooting. Token and secret values are deliberately redacted before anything is ever written to this file.

4. Where your Client Secret lives

Each connected platform requires a developer application (Client ID/Key and Client Secret) that the App's developer registers with that platform. These values are stored in a local configuration file on the developer's own machine, are never bundled into the App's user interface code, never sent to any server, and never appear in application logs.

5. What is transmitted, and to whom

The only network requests the App makes related to your accounts go directly from your device to the official API of the platform you connected (TikTok, Google/YouTube, or Meta/Instagram) — for example, to exchange an authorization code for a token, refresh an expired token, or fetch the profile/analytics data described above. No account data passes through any server operated by the App's developer, because no such server exists.

6. Security practices

  • OAuth tokens are encrypted at rest (AES-256-GCM) with a locally generated key, never stored in plaintext.
  • Token and credential files are restricted to owner-only file permissions on disk.
  • The App's authorization flow uses PKCE and a per-attempt random state value to protect against interception and cross-site request forgery.
  • Error messages and diagnostic logs are sanitized to strip anything that looks like a token or credential before being written or displayed.

7. Data retention and deletion

You control retention directly from within the App:

  • Disconnect revokes the App's access with the platform itself (where the platform's API supports revocation) and deletes the locally stored encrypted token for that account.
  • Remove deletes the local account record entirely.

Because all of this data lives only on your own device, uninstalling the App and deleting its application-support folder removes all of it.

8. Your rights

Since the App does not operate a server and does not collect data about you beyond what's described above (stored only on your own device), most data-subject rights are already in your direct control through the App's own Disconnect/Remove features. For any other question about this policy, contact the developer using the information below.

9. Children's privacy

The App is not directed at children, and connecting a social media account through it requires you to meet that platform's own minimum age and account eligibility requirements.

10. Changes to this policy

This policy may be updated as the App's functionality changes. Material changes will be reflected by an updated "Last updated" date on this page.
